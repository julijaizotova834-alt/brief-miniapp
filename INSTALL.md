# Установка мини-приложения Brief AI — подробная инструкция

Эта инструкция написана в предположении, что ты делаешь это первый раз. Каждый шаг —
с конкретными названиями кнопок и полей, как в интерфейсе Render и GitHub.

Всего нужно сделать 6 шагов:
1. Положить код в GitHub
2. Задеплоить backend (webapp_server.py) на Render
3. Задеплоить index.html через GitHub Pages
4. Связать их друг с другом
5. Настроить кнопку в боте
6. Проверить, что всё работает

Время: 30–60 минут на первый раз.

---

## Шаг 0 — что должно быть готово заранее

- Аккаунт на [github.com](https://github.com) (бесплатный)
- Аккаунт на [render.com](https://render.com) — у тебя уже есть, ты там держишь ботов
- Тот же `TELEGRAM_TOKEN`, `GROQ_API_KEY`, `GEMINI_API_KEY`, `DATABASE_URL`, что используются
  в твоём текущем Brief_bot — мини-приложение работает с той же базой данных и тем же ботом,
  отдельный токен не нужен

---

## Шаг 1 — Положить код в GitHub

1. Зайди на [github.com/new](https://github.com/new)
2. **Repository name**: `brief-miniapp` (можно любое)
3. Поставь **Private** (это твой код, не обязательно светить публично)
4. Нажми **Create repository**
5. На следующей странице будет кнопка **uploading an existing file** — нажми на неё
6. Перетащи туда 5 файлов, которые я тебе прислал: `index.html`, `core.py`,
   `webapp_server.py`, `requirements.txt`, `README.md`
7. Внизу страницы нажми **Commit changes**

Готово — код лежит в GitHub, дальше Render и GitHub Pages будут брать его оттуда.

> Перед загрузкой не забудь вставить в `core.py` свой словарь `PROMPTS` из текущего
> `bot.py` (открой файл в GitHub, нажми на карандаш ✏️ в правом верхнем углу файла,
> чтобы редактировать прямо в браузере).

---

## Шаг 2 — Задеплоить backend на Render

Это серверная часть, которая принимает файлы, гоняет их через Whisper и Gemini,
и отправляет документы в чат.

1. Зайди в [dashboard.render.com](https://dashboard.render.com)
2. Нажми **New +** (синяя кнопка вверху справа) → **Web Service**

   ⚠️ Важно: именно **Web Service**, а не **Background Worker** (твои текущие боты,
   скорее всего, Background Worker, потому что они на polling и им не нужен публичный
   адрес — а этому сервису публичный HTTPS-адрес нужен обязательно)

3. Подключи свой GitHub-аккаунт, если ещё не подключён, и выбери репозиторий `brief-miniapp`
4. Заполни поля:
   - **Name**: `brief-miniapp-backend` (это будет частью адреса)
   - **Region**: тот же, что у твоих текущих сервисов
   - **Branch**: `main`
   - **Runtime**: `Python 3`
   - **Build Command**:
     ```
     pip install -r requirements.txt
     ```
   - **Start Command**:
     ```
     uvicorn webapp_server:app --host 0.0.0.0 --port $PORT
     ```
   - **Instance Type**: Free (для теста) или такой же, как у текущих ботов

5. Спускаемся до **Environment Variables** → **Add Environment Variable**, добавляем по одной:

   | Key | Value |
   |---|---|
   | `TELEGRAM_TOKEN` | токен твоего бота (тот же, что в Brief_bot) |
   | `GROQ_API_KEY` | твой ключ Groq |
   | `GEMINI_API_KEY` | твой ключ Gemini |
   | `DATABASE_URL` | та же строка подключения к Postgres, что у текущего бота |
   | `ALLOWED_ORIGIN` | пока поставь `*` — поправим в шаге 4 |

6. Нужен `ffmpeg` для нарезки длинных записей. Render по умолчанию его не ставит.
   В корне репозитория (там же, где `requirements.txt`) создай файл с именем `apt.txt`
   (без расширения, просто `apt.txt`) и одной строкой внутри:
   ```
   ffmpeg
   ```
   Загрузи его в GitHub так же, как остальные файлы (Шаг 1, пункт 6).

7. Нажми **Create Web Service**

8. Подожди 2–5 минут, пока Render соберёт и запустит сервис. Когда увидишь зелёную
   надпись **Live** наверху — сервис работает.

9. Скопируй адрес сервиса — он будет вида:
   ```
   https://brief-miniapp-backend.onrender.com
   ```
   Он написан крупно под названием сервиса, наверху страницы. **Сохрани этот адрес —
   он нужен в Шаге 4.**

## Шаг 3 — Задеплоить index.html через GitHub Pages

Это сама страница мини-приложения, которую увидит пользователь внутри Telegram.

1. Открой свой репозиторий `brief-miniapp` на github.com
2. Перейди в **Settings** (вкладка сверху, с шестерёнкой)
3. В левом меню найди **Pages**
4. В разделе **Build and deployment** → **Source** выбери **Deploy from a branch**
5. В **Branch** выбери `main` и папку `/ (root)`, нажми **Save**
6. Подожди 1–2 минуты, обнови страницу — появится зелёный блок с адресом вида:
   ```
   https://твой-логин.github.io/brief-miniapp/
   ```
7. Открой этот адрес плюс `index.html` в конце:
   ```
   https://твой-логин.github.io/brief-miniapp/index.html
   ```
   Сохрани этот адрес — это твой адрес мини-приложения, он нужен в Шаге 5.

> Если репозиторий был **Private** — GitHub Pages на бесплатном тарифе работает только
> с публичными репозиториями. Если Pages не включается — зайди в Settings репозитория,
> в самый низ, и смени **Danger Zone → Change visibility** на Public. Секретов в этих
> 5 файлах нет (ключи лежат в Render, не в коде), так что это безопасно.

---

## Шаг 4 — Связать backend и страницу друг с другом

Теперь скажем странице, где искать backend, и backend'у — кому разрешено к нему обращаться.

**4.1. Обновить index.html**

1. Открой файл `index.html` в своём репозитории на GitHub
2. Нажми на карандаш ✏️ (Edit this file) в правом верхнем углу
3. Найди строку (используй Ctrl+F / Cmd+F в браузере):
   ```js
   const API_BASE = "https://YOUR-BACKEND-DOMAIN.example.com";
   ```
4. Замени на адрес из Шага 2, пункт 9, например:
   ```js
   const API_BASE = "https://brief-miniapp-backend.onrender.com";
   ```
5. Внизу страницы нажми **Commit changes**
6. Подожди минуту — GitHub Pages автоматически пересоберёт страницу

**4.2. Обновить ALLOWED_ORIGIN на Render**

1. Вернись в Render → твой сервис `brief-miniapp-backend` → **Environment**
2. Найди переменную `ALLOWED_ORIGIN`, поменяй значение `*` на твой адрес из Шага 3,
   без `/index.html` на конце, например:
   ```
   https://твой-логин.github.io
   ```
3. Сохрани — Render автоматически перезапустит сервис с новой настройкой

## Шаг 5 — Настроить кнопку в боте

Самый простой способ — через @BotFather, без изменения кода бота:

1. Открой Telegram, найди **@BotFather**
2. Отправь `/mybots`
3. Выбери своего бота (Brief_bot)
4. **Bot Settings**
5. **Menu Button**
6. **Edit Menu Button URL**
7. Вставь адрес мини-приложения из Шага 3, пункт 6 (с `index.html` на конце):
   ```
   https://твой-логин.github.io/brief-miniapp/index.html
   ```
8. BotFather попросит название кнопки — напиши, например, `Brief AI`

Готово — теперь рядом с полем ввода в чате с твоим ботом появится кнопка с этим
названием, она открывает мини-приложение.

---

## Шаг 6 — Проверка

1. Открой чат с ботом в Telegram (лучше на телефоне — на десктопе Mini Apps иногда
   работают нестабильно)
2. Нажми кнопку меню (там, где обычно скрепка/меню рядом с полем ввода)
3. Должна открыться страница мини-приложения с приветствием
4. Прикрепи любой аудиофайл — короткий, для первого теста
5. Если всё подключено правильно — появится сообщение «Запись получена» и кнопки
   выбора типа документа
6. Выбери любой тип — через 10–30 секунд в чат с ботом (не в мини-приложении!)
   придут файлы `.docx` и `.txt`

## Если что-то не работает

**Белый экран / ничего не загружается**
Открой мини-приложение в браузере телефона напрямую (не из Telegram) по адресу
из Шага 3 — если там тоже белый экран, значит проблема в GitHub Pages, не в Telegram.
Проверь, что Pages включён (Шаг 3, пункт 6) и что прошла минута после коммита.

**«Ошибка сети» при загрузке файла**
Скорее всего, не совпадает `ALLOWED_ORIGIN` (Шаг 4.2) или backend ещё не проснулся —
на бесплатном тарифе Render сервис «засыпает» после 15 минут без запросов и первый
запрос после сна может идти 30–50 секунд. Подожди и попробуй снова.

**«Неверная подпись initData» / ошибка 401**
Значит `TELEGRAM_TOKEN` на Render не совпадает с токеном бота, через который открыто
мини-приложение, либо мини-приложение открыто не из Telegram (просто в браузере) —
тогда `initData` пустая, это ожидаемо, проверять нужно именно из чата с ботом.

**Документ не приходит после обработки**
Зайди в Render → твой сервис → вкладка **Logs** — там будет видно конкретную ошибку
(чаще всего — неверный `GEMINI_API_KEY`/`GROQ_API_KEY` или не подключился `ffmpeg`,
проверь, что файл `apt.txt` загружен и сервис пересобрался после этого).

**ffmpeg: command not found в логах**
Файл `apt.txt` должен лежать в корне репозитория, на одном уровне с `requirements.txt`,
и Render должен использовать Native Environment (не Docker) — если у тебя Docker-деплой,
`apt.txt` не сработает, нужно добавить `ffmpeg` в `Dockerfile` через `apt-get install`.
